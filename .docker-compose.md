# Docker Compose Setup – Lokale Entwicklung mit Caddy

Verwenden Sie Docker Compose, um die Seite lokal mit Caddy zu servieren und dabei realistische Bedingungen (Caching, Gzip, Security Headers) zu simulieren.

## Voraussetzungen

- Docker & Docker Compose installiert (https://www.docker.com/products/docker-desktop)
- npm installiert (für Build)

## Schnelleinstieg

### 1. Seite bauen

```bash
npm run build
```

Dies erstellt die statische HTML/CSS/JS in `dist/`.

### 2. Docker Container starten

```bash
docker compose up -d
```

Der Webserver läuft jetzt unter **http://localhost** (Port 80).

### 3. Im Browser öffnen

```
http://localhost
http://localhost/page/2/
http://localhost/sammlungen/sommer-2026/
http://localhost/posts/2026-06-20-urban-trilogy/
http://localhost/rss.xml
```

## Häufige Befehle

```bash
# Logs anschauen
docker compose logs -f caddy

# Container stoppen
docker compose down

# Container neustarten (nach npm run build)
docker compose restart caddy

# Alles löschen (Cache, Config)
docker compose down -v
```

## Lokale Entwicklung (mit Hot-Reload)

Während der Entwicklung können Sie gleichzeitig dev-Server und Caddy laufen lassen:

```bash
# Terminal 1: Dev-Server (Auto-Reload bei Änderungen)
npm run dev
# Öffnet http://localhost:4321

# Terminal 2: Build-überwachen und Container neu laden
npm run build && docker compose restart caddy
# Öffnet http://localhost (mit optimiertem Build)
```

## Caddy-Konfiguration

Die `Caddyfile` im Projekt-Root definiert:

- **Statische Asset-Caching**: `/_astro/*` → 1 Jahr immutable
- **RSS-Feed-Caching**: `/rss.xml` → 1 Stunde
- **HTML-Seiten**: 5 Minuten Revalidierung
- **Gzip-Kompression**: Automatisch für HTML/CSS/JS
- **Security Headers**: `X-Frame-Options`, `X-Content-Type-Options`
- **SPA-Fallback**: Unbekannte Routen fallback auf `index.html` (falls nötig)

## Produktions-Deployment

In der Produktion:

1. **Domain anpassen**: `astro.config.mjs` mit echtem Host konfigurieren
2. **Build**: `npm run build`
3. **Caddyfile für Produktion**: Domain statt `localhost` verwenden
4. **Docker starten**: `docker compose up -d`
5. **HTTPS automatisch**: Caddy holt sich ein Let's Encrypt-Zertifikat

**Beispiel Caddyfile für Produktion:**
```caddyfile
example.com {
  root * /srv
  file_server
  
  @assets path /_astro/*
  header @assets Cache-Control "public, immutable, max-age=31536000"
  
  @rss path /rss.xml
  header @rss Cache-Control "public, max-age=3600"
  
  header Cache-Control "public, max-age=300"
  header X-Frame-Options SAMEORIGIN
  header X-Content-Type-Options nosniff
  
  encode gzip
  try_files {path} {path}/ /index.html
}
```

## Troubleshooting

**Port 80 bereits in Benutzung?**
```bash
docker compose down
# oder Port ändern in compose.yml:
# ports:
#   - "8080:80"
```

**Bilder werden nicht angezeigt?**
```bash
npm run build
docker compose restart caddy
```

**Cache-Probleme?**
```bash
# Browser-Cache leeren (Ctrl+Shift+Delete)
# oder
docker compose down -v  # Cache löschen
docker compose up -d
```
